## 真正的系統驗收規則（尚未達成）

1. **合法來源**：確認圖層授權、更新日期、可否批次查詢，及其是否可被當作法定都市計畫分區依據。
2. **行政區與分區**：每個目標都要用官方來源確認座標落在桃園區的「商業區」，住宅區、未知、混合分區均不得自動發布。
3. **候選整合基地**：使用可合法取得的建物輪廓、道路、分區或地籍資料（有則使用），計算相鄰建物群、連續面積、臨路面寬、路寬、分割地號數。不得把建物面積當土地面積，不得由低矮建物猜屋齡。
4. **分數與解釋**：現有初版權重 25（連續面積）+20（相鄰建物）+20（低樓層比例）+15（面寬）+10（路寬）+10（地號數），任何缺漏欄位不得補造或正常排名。
5. **實勘驗證**：首批目標至少 10 處，都必須可定位、來源可追溯、官方商業區確認；抽查至少 5 處，人工評估值得再調查比例目標 60%。
6. **通知**：僅對已核准且未通知過的目標建立 Issue。未經審核的代碼樣本、診斷資料與空名單不推播。

## 已發現的風險

- 目前官方 GIS 查詢的圖層雖名為「都市計畫使用分區」，其大量小圖形與代碼欄位並未證明能直接還原法定分區，不能偷換定義。
- 查詢範圍只是測試框，**不是桃園區正式行政界線**。
- 目前的分數是「資料齊全時如何排優先勘查」的規則，不是由真實圖資跑出來的分數。
- Public 儲存庫與 GitHub Issues 內容公開，禁止放入地主姓名、電話、談判紀錄等個資與機密。

## 下一道技術關卡

先透過市府都市計畫服務或官方圖例、資料字典，確認可靠的商業區幾何資料、分區代碼定義與可批次取得的合法來源。取得後先做小範圍地圖人工核驗，再開啟候選街廓空間交集與排序。不要跳過這道門檻直接產生開發名單。

4. **資料實質辨識：** 已測的 ArcGIS 圖層名稱雖為「都市計畫使用分區」，但欄位值不具可直接理解的分區名稱，亦無代碼字典；**目前不能當作完成商業區驗證的資料來源**。

### 新增硬性資料門檻

- **行政區門檻：** 應使用正式桃園區行政區多邊形求交集，不能只用桃園舊城測試矩形。
- **商業區門檻：** 只有官方圖例／屬性清楚對應「商業區」且可證實時才通過，任何不確定／未完成屬性對照者皆不得產出已驗證名單。
- **跨界候選：** 遇到商業區、住宅區或行政區邊界穿越建物／街廓時，不可憑中心點歸類。保守停止、標記待人工核對。
- **資料完整性：** 記錄主管機關、法定計畫名稱、公告或更新日期、原始檔版本、坐標系統、來源網址，以及抽樣人工驗證結果。尚未取得者禁止把 `verification_status` 改成已驗證。
- **發布控制：** 在未通過至少 10 個已知分區控制點（含商業區與住宅區）的交叉驗證前，維持 `docs/targets.json` 空白、只運行診斷。

**驗收目標：** 先能輸出可重現且可檢查的「桃園區法定商業區範圍」，再啟動建物套疊與整合評分；不要把圖資連線成功等同搜尋完成。

## 2026-11-25 當場查證的新發現

- 官方桃園市都市計畫地理資訊服務網 `https://urplanning.tycg.gov.tw/gisMap/Map.aspx` **已有**「行政區或地段 → 行政區、使用分區 → 分布圖」的互動查詢；可用來**人工查看**「桃園區 + 商業區」，另有「都市計畫區 → 使用分區 → 顯示使用分區圖」。
- 從該官網前端 `Scripts/map/mapPage_main.js` 辨識出它實際引用的服務 `https://urbandatasrv.tycg.gov.tw/server/rest/services/TY_UPGIS/TYMap_SDE/MapServer`，但 GitHub Actions 於 2026-11-25T13:28Z 連線逾時，**無法擷取其圖層與法定商業區幾何資料**。
- 該資訊不可由先前 `3dmap.tycg.gov.tw` 的 AA 欄位猜測取代；截圖、地圖顏色、地標中心點，也無法當作全部商業區多邊形的正確證明。
- 官方網站若僅供個別互動查詢、缺少可批量合法介接的圖資，就必須向桃園市政府都市發展局索取「桃園區適用最新都市計畫商業區 GIS 向量資料、圖層屬性定義、公告版本、坐標系統、使用授權」。**取得前不發布已驗證的商業區邊界或土地開發案**。

現場工作替代方法：開啟市府圖台，選「行政區或地段」，行政區選「桃園區」，使用分區選「商業區」，按「分布圖」；取得查詢結果後再以官方都市計畫圖對照。若要程式自動搜地，仍須一份合法的向量圖形檔，不能靠人工網頁顯示自動推定多邊形。
