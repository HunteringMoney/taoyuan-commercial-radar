## 產出

- `scripts/pilot_georeference.py`：至少 4 個**獨立核對**的影像控制點，最小平方法仿射校正、逐點留一誤差檢查，再轉紅色像素為草稿 GeoJSON。沒有控制點或誤差超標會停止，輸出一律標 `verified_zoning_geometry=false`。
- `config/pilot_control_points.json`：已填官方 55-1 地號中心與影像圖釘大概位置；`control_points` 保持空白，因為圖釘不是精確控制點。待從官方圖台選取至少 4 個分布良好的道路交點／地籍角點，逐一記錄像素、WGS84 座標與來源 URL。
- `scripts/pilot_scout.py`：使用官方圖台查詢結果和 OSM 建物輪廓，僅收整個輪廓落於商業區圖形的建物，再分群。住宅區、其他分區和跨界輪廓均排除。當場產出 **1 個實際座標的待查建物群**，位於 `(121.3126472, 24.9961143)`，包含 6 個 OSM 建物輪廓；見 `docs/pilot_scout_candidates.json`。它不是 6 筆地號，也不是已確認開發基地。
- 正式 `docs/targets.json` 維持空名單。沒有完成截圖定位與法定計畫版本查核，不能把待查線索升級成正式目標。

## 重現方式

安裝 `shapely>=2,<3`、`numpy>=2,<3`、`opencv-python-headless>=4.10,<5`。使用者提供的原始截圖存成 `input/pilot.png`。先在官方地籍圖與都市計畫圖核對並填入 `config/pilot_control_points.json` 的至少 4 個控制點，再執行：

```bash
python scripts/pilot_georeference.py --image input/pilot.png --control-points config/pilot_control_points.json --output input/pilot_red_draft.geojson --report input/georeference_report.json
```

使用官方第 1、2 層的小範圍 `f=geojson` 查詢結果和 OSM Overpass `way["building"]` `out geom` 匯出為本機輸入。來源、時間、範圍、授權與原始回應雜湊應保留在本機；不可在 public 儲存庫放入未授權原始圖資或個資。再執行：

```bash
python scripts/pilot_scout.py --zoning input/official_commercial_raw.geojson --parcel input/anchor_parcel_raw.geojson --osm input/osm_buildings_raw.json --scope-output input/pilot_official_reference.geojson --output input/pilot_scout_candidates.json
```

`pilot_official_reference.geojson` 是**本機診斷參考層**，不應與尚未產生的截圖草稿 GeoJSON 或法定分區公告向量混同。正式發布仍須核對官方計畫版本、截圖控制點、候選建物及地籍；住宅區一律不得納入。

## 驗證結果與卡點

- 本機 9 項幾何與校正單元測試通過；舊 Actions run `46121900529` 的候選測試失敗，原因是 `shapely.ops.transform` 對座標 tuple 做 Python 重複運算造成 GEOS 記憶體錯誤；改用 `shapely.affinity.scale` 後舊 5 項測試本機通過。
- 尚無 4 個獨立控制點，故**未宣稱截圖完成地理校正**。試驗 GeoJSON 程式已可在合成圖上測試；實圖輸出被正確擋下。
- 市府 MapServer 當下可讀，不代表可任意批量重製、公開其全部向量；此處只以小範圍查詢作診斷。最新公告版本及使用授權仍待查。
- OSM 小範圍只有 82 個 way，能形成 1 群；不能推稱已有 10 處基地或全區涵蓋完成。
